# 多語言輸入練習遊戲：人工驗收清單

依據 [2026-09 重製交付規格](https://linear.app/bolas-dev/document/2026-09-重製交付規格與-symphony-驗收計畫-6651a7befe8c) 與 [玩家操作說明](player-guide.md) 驗收。此清單描述預期結果，不是測試通過報告。

**目前所有遊戲人工驗收均為「未執行」，包含實際瀏覽器及真實作業系統 IME。** 文件建立或靜態檢查不等於遊戲已通過驗收；自動化鍵盤事件也不能代替真實 OS 輸入法操作。

## 執行與記錄方式

請在整合後的桌面瀏覽器版本逐項操作，記錄以下環境，再將各項「未執行」改為「通過」或「失敗」，並附實際結果或證據。若環境不足或場景尚未重現，維持「未執行」並記錄原因，不可推定通過。

| 記錄欄位 | 待填內容 |
| --- | --- |
| 驗收人、日期 | 未執行／待填 |
| 版本、分支或提交識別、遊戲網址 | 未執行／待填 |
| 作業系統及版本 | 未執行／待填 |
| 瀏覽器及版本、視窗尺寸、縮放比例 | 未執行／待填 |
| 中文 OS IME 名稱、版本及模式 | 未執行／待填 |
| 日文 OS IME 名稱、版本及模式 | 未執行／待填 |
| 減少動態效果設定 | 未執行／待填 |
| 證據位置與失敗項目說明 | 未執行／待填 |

每項可獨立重開一局，以免前項操作影響結果。需要特定棋盤排列時，記錄操作或重現方式；只有自然遊玩卻未遇到該場景時，不算通過。

## A. 來源解析與限制

下列範例中的 `␠` 僅表示一個 U+0020 空格；實測請輸入真正空格，不要輸入 `␠` 符號。Unicode 碼點序列也需使用實際字元，不是字面上的 `U+...` 或跳脫文字。

| 編號 | 操作 | 預期結果 | 結果 |
| --- | --- | --- | --- |
| A01 | 分行貼上 `你好`、`こんにちは`、`Hello world`、`今天は good day` 並開始。 | 四行各自成為完整題目，混合語言可正常出題與作答。 | 未執行 |
| A02 | 貼上 `␠你好␠`，穿插空白行、只有空格或 Tab 的行。 | 行首尾空白移除，空白行忽略，只留下有效題目 `你好`。 | 未執行 |
| A03 | 來源加入 `Hello␠␠world`，等待該題出現，分別提交一個及兩個內部空格的答案。 | 來源保留兩個內部空格；一個空格不匹配，兩個空格才匹配。 | 未執行 |
| A04 | 來源放入兩行 `你好` 及一行 `Hello`。 | 重複行不去重，保留為兩份「你好」的抽題權重；不要求少量隨機出題恰好呈現 2:1 比例。若介面無法直接呈現來源解析結果，需另附核心驗證證據，不能僅憑目測機率判定。 | 未執行 |
| A05 | 來源留空，再改成只有空白行後嘗試開始。 | 不進入無有效題目的遊戲，呈現可理解的文字提示。 | 未執行 |
| A06 | 輸入 500 行有效短題目（可重複），另加空白行；再增加第 501 行有效題目。 | 500 題可接受，空白行不占有效題數；501 題顯示錯誤且不開始，不靜默丟棄超限行。 | 未執行 |
| A07 | 分別使用由 40 個及 41 個 `a` 組成的單題。 | 40 碼點可接受，41 碼點顯示錯誤且不開始，不截短成 40 碼點。 | 未執行 |
| A08 | 分別使用 40 個及 41 個 `😀`（U+1F600）作為單題。 | 每個 `😀` 算一個碼點，不以 UTF-16 的兩個碼元誤算；40 個可接受，41 個超限。 | 未執行 |
| A09 | 修正 A06 或 A07 的超限來源，再開始。 | 修正後可開始；使用完整有效來源，沒有沿用錯誤時截斷或過期的題庫。 | 未執行 |

## C. 完整匹配、Unicode 與計分

各匹配測試都先確認目標題目正在場上；測試不匹配時，避免場上存在恰好符合錯誤答案的另一題。

| 編號 | 操作 | 預期結果 | 結果 |
| --- | --- | --- | --- |
| C01 | 目標為 `Hello world`，先只鍵入完整答案，稍等，再按 Enter。 | 未按 Enter 時不消除；提交後消除一題、增加 100 分及一次消除數。 | 未執行 |
| C02 | 對 `Hello` 依序提交 `Hel`、`hello`、`Hello!` 及無關文字。 | 部分文字、大小寫差異、額外標點與錯字均不匹配；不消除、不扣分，每次未匹配提交計入未匹配數。 | 未執行 |
| C03 | 對 `Hello` 分別提交 `␠Hello`、`Hello␠`，最後提交 `Hello`。 | 提交不 trim，前兩次不匹配，最後一次匹配。 | 未執行 |
| C04 | 來源用 `café`，答案用 `café`（末尾為 U+0065、U+0301）；交換來源與答案的形式再測一次。 | 兩個方向都經 NFC 正規化後完整匹配，每次只消除一題並加 100 分。 | 未執行 |
| C05 | 題目用 `が`（U+304C），答案用 `か` 加組合濁音符（U+304B、U+3099）。 | NFC 等價的日文形式可匹配，沒有把組合符號遺漏或當成另一題。 | 未執行 |
| C06 | 題目用 `A`，提交全形 `Ａ`（U+FF21）；題目用 `e`，提交 `é`。 | 均不匹配；NFC 不等於全半形轉換，也不移除重音符號。 | 未執行 |
| C07 | 以包含 `😀` 的題目完成提交，再連續正確消除三題並穿插錯誤答案。 | 非 BMP 字元可完整顯示與匹配；三次消除合計 300 分，錯誤不扣分，消除數與未匹配數各自正確。 | 未執行 |

## D. 真實 OS 輸入法（必須人工操作）

本節須使用實際作業系統中文、日文 IME，記錄 OS、瀏覽器、輸入法及版本。貼上已完成的文字、模擬 `composition` 事件或一般自動化輸入，均不能作為本節通過證據。沒有可操作的人工環境時，結果保持「未執行」。

| 編號 | 操作 | 預期結果 | 結果 |
| --- | --- | --- | --- |
| D01 | 用真實中文注音或拼音 IME 作答場上的中文題；組字、選字後，用 Enter 確認候選字。 | 確認組字的 Enter 只完成文字，不提交、不消除、不加分，也不增加未匹配數。 | 未執行 |
| D02 | 接續 D01，確認組字結束，再按下一次 Enter。 | 這次才提交完整文字，正確時只消除一題並加 100 分。 | 未執行 |
| D03 | 用真實日文 IME 輸入場上的日文題，進行假名／漢字轉換，用 Enter 確认，再按下一次 Enter。 | 首次 Enter 只確認組字，統計不變；下一次 Enter 才判定答案，沒有提前提交或重複提交。 | 未執行 |
| D04 | 在兩種 IME 中，分別測試組字中按 Enter、候選選擇確認及組字剛結束的 Enter。 | 從 compositionstart 到 compositionend 期間，以及標示 isComposing 或 keyCode 229 的 Enter 均不判定；結束組字的同一次按鍵不能漏送為答案。若需診斷事件，可附事件紀錄，但仍須實際 OS 操作。 | 未執行 |
| D05 | 組字中先選錯候選字，改選正確文字，再確認及提交；另以已完成組字的錯誤答案提交。 | 編輯與候選確認不增加未匹配數；只有組字完成後明確提交的錯誤答案才計一次未匹配，不扣分。 | 未執行 |

## E. 棋盤、重複題與加速

| 編號 | 操作 | 預期結果 | 結果 |
| --- | --- | --- | --- |
| E01 | 開始後觀察棋盤及連續生成的欄位。 | 棋盤為 4 欄 × 8 格；欄位使用 shuffle bag，每袋四欄各選一次。跨袋交界可能連續同欄，不能因此誤判失敗。 | 未執行 |
| E02 | 在方塊仍下落時提交正確答案；再等另一塊落定後提交。 | 下落與落定的方塊都能消除，每塊各加 100 分。 | 未執行 |
| E03 | 在同欄堆疊多塊後消除中間或底部方塊。 | 上方方塊補位，方塊不穿越、不重疊，其他欄仍遵守各自堆疊。 | 未執行 |
| E04 | 讓同字題出現在堆疊高度不同的欄，提交一次。 | 只消除最高堆疊欄中的同字題，其他同字題仍在；只加 100 分。 | 未執行 |
| E05 | 讓候選同字題所在欄堆疊高度相同、方塊位置不同，再提交。 | 優先消除位置較低者；再次提交才能消除下一個同字題。 | 未執行 |
| E06 | 讓同字題的欄堆疊高度及位置都相同，記錄生成先後後提交。 | 消除較早生成者。若無法重現此排列，保持未執行並記錄，不能以 E04 或 E05 代替。 | 未執行 |
| E07 | 持續消除以維持遊戲，記錄有效遊玩時間 0、20、40 秒附近的生成及落速。 | 初始間隔 2400 毫秒、每秒 0.75 格；20 秒後為 2200 毫秒、每秒 0.85 格；40 秒後為 2000 毫秒、每秒 0.95 格。 | 未執行 |
| E08 | 持續遊玩跨過 180 秒及 260 秒，觀察加速上限。 | 生成間隔最低 600 毫秒，落速最高每秒 2 格；之後不再超出上限。未能維持到該時間則記錄未執行，可另附核心計時驗證證據。 | 未執行 |

## F. Game Over、結算與重開

| 編號 | 操作 | 預期結果 | 結果 |
| --- | --- | --- | --- |
| F01 | 停止消除，觀察第一個落定堆滿 8 格的欄。 | 該欄落定至第 8 格立即 Game Over；不等待其他欄滿，也不把尚未落定的方塊誤算為滿欄。 | 未執行 |
| F02 | Game Over 後等待並嘗試輸入正確答案、按 Enter。 | 計時、生成、移動與答案判定全部停止；棋盤與結算數值不再變動。 | 未執行 |
| F03 | 在已記錄消除次數、未匹配次數及有效遊玩時間的一局查看結算。 | 顯示分數、消除數、未匹配數與存活時間；分數等於消除數 × 100，資料屬於剛結束的一局。 | 未執行 |
| F04 | 在結算選擇「再玩」。 | 沿用來源，棋盤清空，分數、消除數、未匹配數及存活時間歸零，速度恢復初始值；重新倒數 3 秒，開始後焦點回作答區。 | 未執行 |
| F05 | 在結算選擇「修改來源」，換成完全不同的有效題目並開始。 | 返回可編輯的來源畫面，新局使用修改後來源，舊題與舊統計不殘留，重新倒數。 | 未執行 |
| F06 | 連續完成 Game Over → 再玩至少三次。 | 各局獨立，沒有重複計時器造成生成加倍、速度異常或一次提交重複加分。 | 未執行 |

## 文件交付檢查

本工單只交付 `docs/player-guide.md` 與 `docs/acceptance.md`。主機可用以下命令確認兩份非空 Markdown 存在；此命令不驗證遊戲行為，也不改變上述人工驗收狀態：

```sh
test -s docs/player-guide.md && test -s docs/acceptance.md
```

另需人工核對兩份文件使用繁體中文、涵蓋規格中的操作與預期結果，且本工單未修改 `package.json`、`src` 或其他檔案。只有實際執行並留下結果的遊戲項目才能標為通過。
